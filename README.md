# Equipment Checkout Calendar

A Flutter app for two people to sign out shared equipment and prevent
double-booking in real time. Both phones see each other's bookings instantly
via Firebase Firestore.

More equipment can be added inside the app at any time.

## Features
- **Real-time calendar** — colored dots show which equipment is booked; both
  phones update the moment a booking is added, changed, or deleted
- **Double-booking prevention** — the app blocks any checkout that conflicts
  with an existing reservation
- **Two users** — tap your name at launch; rename yourself from the avatar menu
- **Multi-day checkouts** — single day or a full week, your choice
- **Equipment management** — add, rename, recolor, or deactivate equipment
- **Works offline** — Firestore caches data locally; bookings sync when you
  reconnect

## Setup (one-time, done once by either person)

### 1. Install Flutter
https://docs.flutter.dev/get-started/install

### 2. Create a Firebase project
1. Go to https://console.firebase.google.com and click **Add project**
2. Give it a name (e.g. "Equipment Checkout") — disable Analytics if asked
3. In the left sidebar, open **Firestore Database → Create database**
4. Choose **Start in test mode** (the `firestore.rules` file in this repo
   replaces those rules — deploy it in step 5)

### 3. Generate the Flutter Firebase config
```bash
# Install the FlutterFire CLI (once per machine)
dart pub global activate flutterfire_cli

# Inside the project folder, run:
flutterfire configure
```
Follow the prompts — select your Firebase project and the platforms you need
(Android / iOS). This creates `lib/firebase_options.dart` automatically.

### 4. Deploy Firestore rules
```bash
# Install Firebase CLI if you haven't already
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```

### 5. Run the app
```bash
flutter create . --project-name equipment_checkout --org com.equipmentcheckout
flutter pub get
flutter run
```

### 6. Share with the other person
Commit `lib/firebase_options.dart` to the repo — it's safe to share (Firebase
security is handled by the rules, not by keeping this file secret).

The other person pulls the repo, runs `flutter pub get`, and they're on the
same live database.
